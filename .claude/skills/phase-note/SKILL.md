# 学習ノートの作成

引数にフェーズ番号(例: `2`)を受け取る。無ければユーザーに聞く。

## 手順

1. `docs/architecture.md` の該当フェーズを読み、「作るもの」「計測」「理解すること」「商用CDNとの対応」を確認する
2. 数字を集める
   - 直近のk6結果: `loadtest/results/` 配下の最新ファイル、またはユーザーが貼った出力
   - Prometheus: `curl -s 'http://localhost:9090/api/v1/query?query=...'` で必要な値を取る(ヒット率、オリジンRPS、レイテンシp50/p95/p99 など)。コンテナが起動していなければ、その旨を書いて推測値は書かない
   - 前フェーズのノート(`docs/notes/phase{N-1}.md`)があれば比較対象にする
3. ユーザーに「気づいたこと・意外だったこと・疑問」を聞く。ユーザーの言葉をノートの中心に置き、Claudeの解説は補足に回す
4. 下のテンプレートで `docs/notes/phaseN.md` を書く(既存なら追記・更新)
5. 書いた内容を短く報告し、`vN.0.0` タグを打つか確認する(タグはユーザーの了承後に打つ)

## テンプレート

```markdown
# Phase N: <フェーズ名>

- 日付: YYYY-MM-DD
- タグ: vN.0.0

## やったこと
- 実装・設定の変更点(ファイルへのリンク付き)

## 計測条件
- k6シナリオ、VU数、時間、アクセス分布、オリジンの遅延設定

## 結果
| 指標 | 前フェーズ | 今回 |
|---|---|---|
| オリジンへのRPS | | |
| p50 / p95 / p99 | | |
| ヒット率 | | |

## 気づき
- (ユーザーの言葉)

## 商用CDNとの対応
- CloudFront / Google Cloud CDN / Akamai でいうと何か

## 疑問・次にやること
-
```

## 守ること

- 数字は実測値のみ。取れなかった値は「未計測」と書く
- 文章は短く、具体的に。AIっぽい装飾(絵文字、過剰な太字)は使わない
